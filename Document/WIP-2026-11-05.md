## 未解决

### A. 停顿测试曾偶发红（三跑一红；现已连续三次通过）
`Delivery.NPC.PedestrianWalk` 里**原有的**两条停顿断言曾偶发失败
（「走出窗口之后会停」「停着不前进」）。本次将停顿测试的让路功能关闭，
让其只验证停顿；另外将让路计时改为在短暂无遮挡时逐渐衰减，
而不是立即清零。新增普通路人 500 帧的范围与停顿检查。修改后完整测试连续三次通过。
真实关卡中是否彻底消除偶发站住，仍需 PIE 观察。

- 我先前给的「生成时按默认区间 700~2600 抽 `DistanceUntilPause`、测试预算不够、
  约 18% 偶发」这个解释**已被证伪**：预算从 2000 cm 加到 7000 cm 之后照样红，
  而且失败时距离**每次都是同一个 2250**（真随机的话这个数会变）。
- 2250 = 250 + 200 帧 × 10 cm，也就是**人走到 2250 就不再前进**，预算全耗在原地。
- 怀疑是我加的让路逻辑有个真 bug：

      if (bBlocked) { YieldElapsed += DeltaTime; if (YieldElapsed < MaxYieldSeconds) return 0; }
      else          { YieldElapsed = 0.f; }

  **障碍只要间歇出现，这个超时就永远不触发**——挡住一帧攒一点、空一帧立刻清零。
  这正是注释里说要避免的死锁，换了个形式留下来了。
  交通车的 `BlockedElapsedTime` 是同一个结构，大概有同一个问题。
  现已将 `YieldElapsed` 改成**衰减**而不是瞬间清零。
- **但还没证实**这就是那条测试红的原因：那个测试世界里只有一个路人，
  谁在挡它还没查出来（探测查 `Pedestrian`/`PhysicsBody`/`Pawn`/`Vehicle` 四种物体类型，
  空世界里本该一个都扫不到）。所以也可能只是测试搭建的问题。
- 实机影响：如果那个 bug 是真的，表现是**偶尔有路人贴着别人站住不走**。

### B. 路人手臂僵硬（用户反馈，还没动）
用户说老奶奶最自然，中年男/老爷爷手臂僵硬。已经确定的结构性原因：
- 六个路人**共用同一套程序化步态参数**；
- `UpdateProceduralGait` **只写上臂、前臂从来不动**（肘关节不弯），
  整条手臂是从肩膀甩出去的一根棍子。

角色之间唯一的差异来源是各自绑定姿势的手臂指向（`CacheArmRestDeltas` 是按实测方向算的）。
**下一步应该先量六个模型的绑定姿势手臂指向，不要猜**。
可能的改进：加肘部弯曲（前臂带相位滞后）、手臂摆动相对腿部加一点滞后、
必要时给 `FDeliveryPedestrianKind` 加按种类的参数覆盖。
