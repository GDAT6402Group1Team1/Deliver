# 摩托车程序化骑手

## 分工与更新顺序

摩托车仍按原来的运动学驾驶规则移动。只有车上的独立骑手网格变形；它不模拟物理、不参与碰撞，也不向车辆施力。F 上下车、P 视角和原驾驶参数没有改变。

1. `DeliveryMotorbikeRider.cpp` 从车速变化、转向、竖直运动和交通撞击生成表现输入。驾驶者本机即时计算，服务器约每 0.05 秒刷新复制状态，远端只读取这些状态，不把它们写回驾驶逻辑。
2. 车身和车把先更新变换。骑手组件通过 Tick 前置依赖在车之后更新。左右手目标是 BarPivot 的子组件，脚目标是 MeshAlign 的子组件，因此目标不会被骑手自身的摆动带走。
3. `DeliveryRiderAnimInstance.cpp` 的 PreUpdate 在游戏线程复制输入、目标位置和骨架数据，并推进有幅度上限的阻尼弹簧。加速后仰、刹车前扑、转弯侧倾、风摆和撞击都从这里产生。换驾驶员或无人驾驶时清空弹簧。
4. `DeliveryRiderPose.cpp` 在动画求值时从参考坐姿重新生成髋部小幅起伏、胸腰和头的姿势，再解四条肢体。计算只用快照，不在动画线程读取车辆或场景组件。
5. 求解结果由组件空间转回骨骼局部空间交给 SkeletalMesh。每帧重新从参考姿势开始，避免累计旋转和越晃越歪。

## 手脚为什么不会跟着身体飘

默认从模型原坐姿的手腕、脚踝变换自动标定四个目标，保留原来手握车把、脚踩踏板的位置和方向。仅由腿部可达性限制起伏；手臂够不到车把时，用腰部旋转连续地把肩送近车把，再用两段式 IK 求肘、膝和末端方向，保留上下肢长度，不靠拉伸骨骼。不要把手臂重新加入全身缩幅判定：手臂跨过可达边界时会把整套身体动作突然压到零，强风摆测试曾出现 5.178 cm 的单帧跳变，移除这条耦合后降到 0.761 cm。

目标是骨骼末端原有抓握偏移，不是重新吸附车把网格的中心。更换模型时需要重新校准。关闭 `bAutoCalibrateRiderContacts` 后可编辑 LeftHandGrip、RightHandGrip、LeftFootPeg、RightFootPeg；不合理的远距离目标不保证可达。

## 蓝图和参数

当前风摆：直行保持迎风后仰，不做周期性左右摇头。默认头部后仰目标约 14～42°、限幅 45°；身体前后阵风系数 .55，转弯侧倾乘 1.6、侧向阵风系数 .95，头部转弯滞后回摆系数 .6。动作强于上一版，仍由阻尼弹簧平滑。按用户要求，手部允许最多 5 cm 的短暂偏离（HandSlack 也经过弹簧平滑，停车归零）；脚保持原来的 IK 贴合，不拉长骨骼。身体不再为消除这5cm间隙而过度向握把收缩。

`/Game/Vehicle/Motorbike/BP_Motorbike` 使用新建的 `ABP_MotorbikeRider`。动画蓝图继承原生 `DeliveryRiderAnimInstance`，姿态通过原生动画代理 Evaluate 输出；并非在空 AnimGraph 中缺了 IK 节点。若以后要改成图节点实现，必须同时改代理，不能直接在图里叠第二套姿势。

蓝图的 `Motorbike / 骑手动画 / RiderAnimationSettings` 提供风压、加减速惯性、转弯侧倾、撞击幅度、颠簸高度、弹簧频率和阻尼。频率越高跟随越快，阻尼越低回弹越明显。坐姿资产、材质槽和驾驶员材质映射沿用原实现。

迁移脚本 `Content/Python/setup_motorbike_rider.py` 只创建动画蓝图并更新摩托车蓝图，不改输入、不导入模型、不保存关卡。运行完应重启编辑器或用另一次命令行加载检查资产引用。旧整人跟转和直接改单根脖子的代码已移除，相关旧属性仅保留序列化兼容。

## 验证与边界

Automation 前缀：`Delivery.Vehicle.Rider`。

本次放宽手部贴合的加强版 Game/Editor 编译及三项 Automation 测试通过：运行时头部角度变化 13.39°（上一版 8.18°），最大接触误差 4.9010 cm，最大单帧头部位移 1.345 cm。另有脚部误差 <0.2 cm、单帧头部角度变化 <12°的断言通过。严格零容差模式的资产接触测试仍通过。以上为自动化数值结果，不代表已完成地图外观或双人验收。

- Spring：多帧率、卡顿、大输入、回正和幅度限制。
- AssetContacts：重新加载已保存蓝图，检查真实坐姿骨架、动画类；扫描左右极限转向及前后/左右倾，验证接触误差和骨长。
- AnimationRuntime：创建真实车辆和骑手 SkeletalMesh，运行动画蓝图代理，检查连续转向、加减速时接触点、身体实际移动及下车清空姿势。

自动化数值测试不能替代外观验收。仍需在地图中检查上下车、倒车、急刹、坡道、台阶、撞击，以及双人 Listen Server 下的动作、延迟和材质表现。没有加入衣物模拟或全物理骑行；车辆驾驶网络结构沿用原项目，本轮只补骑手表现状态。
