# 外侧车道生成路灯样条线：实施说明

## 需求与范围

以现有关卡的**外侧交通车道**为基础，向道路外侧生成平行样条线，作为后续布置路灯的路径。例如：

`Lane_MainRoad_R003_-0540_S05` → `light_spline_MainRoad_R003_-0540_S05`

全部新 Actor 放入 World Outliner 的独立文件夹 **`light_spline`**，样条在编辑器里显示为红色。这里的文件夹指关卡大纲文件夹，不是 Content Browser 资产目录。

生成工具：`Content/Python/gen_light_splines.py`；在当前地图的编辑器控制台执行 `py gen_light_splines.py`。只读检查：`py check_light_splines.py`。实际生成数量和参数记录在 `Saved/light_splines.json`，保存后校验结果在 `Saved/light_splines_verified.json`。本工具只生成路径，不放路灯。

当前实现采用外侧车道逐点水平向外偏移 410 cm，高度沿用已贴合路面的车道再抬高 3 cm；**尚未对路肩地面重新探测**。这是沿交通线建立平行布灯路径，不保证每个控制点都贴住路外地面，之后实际摆灯时应单独处理灯脚落地。

### 已修复：生成后退回默认 100 cm 两点样条

2026-10-21 实测复现：先写点，再用 `set_editor_property` 设置颜色和实例覆盖，会触发组件重建，最终只剩默认两点、100 cm。修复为先设置 `spline_has_been_edited`，重新获取组件后写点，颜色改用 `set_unselected_spline_segment_color` / `set_selected_spline_segment_color` / `set_tangent_color`。临时地图保存重载对比：旧顺序剩 2 点、100 cm，新顺序保留 10 点、1855.4 cm。生成器现在逐点回读验证，失败停止保存。重新执行同一生成命令会修复现有生成物，无需手动删除。

## 已核对的项目依据

见 `Content/Python/gen_traffic_lanes.py`：

- 主路宽度配置为 1800 cm，车道偏移为 `-540 / -180 / +180 / +540 cm`，因此只取 **±540** 两条外侧车道。
- 次路宽度配置为 1080 cm，车道偏移为 `±180 cm`，两条都属于外侧车道。
- `Lane_*_Sxx` 是普通车道路段；路口连接线另外生成。第一版只处理普通路段，不沿路口转弯线生成。
- 车道存在反向点序，不能把“沿车道前进方向的右边”一概当成路外侧。
- 道路源样条在 `PS2DEM/Splines/MainRoad`、`PS2DEM/Splines/BranchRoad`；应按现有脚本的道路 ID 对应规则查找源道路，不能假设 Actor label 就等于 `R003`。

## “略宽于车道”的执行定义

指两侧新路径向路外扩开，**不是单纯把样条显示线加粗**。建议先按“道路边缘之外 50 cm”做预览；这是待目视确认的初始值，不是已经测定的路肩位置。

| 道路 | 外侧车道距道路中线 | 新路径距道路中线 | 相对车道向外偏移 |
| --- | ---: | ---: | ---: |
| 主路 | 540 cm | 900 + 50 = 950 cm | 410 cm |
| 次路 | 180 cm | 540 + 50 = 590 cm | 410 cm |

若实际想要的是紧挨交通线，只需改为较小的 `OutwardOffset`（例如 50～100 cm），但这样仍可能在路面内，不适合作为路灯落地位置。正式铺设应以实际路缘、路肩和障碍物为准。

## 推荐实现

1. 创建一个简单的 `BP_LightSpline`：根组件 + 一个 SplineComponent，不带交通 Box、车辆逻辑或碰撞。避免直接复制 `BP_TrafficLine1`，否则会把交通探测逻辑一起复制过去。组件应定义在蓝图中，避免临时 Python 加组件后保存不完整的问题。
2. 新建编辑器脚本 `Content/Python/gen_light_splines.py`。先提供只读预览模式：列出外侧车道、对应道路、偏移距离和预计生成名称；找不到源道路时明确报错并跳过，不猜方向。
3. 先只生成示例 `Lane_MainRoad_R003_-0540_S05`，确认向路外偏移，再生成同一道路两侧，最后扩展到全图。
4. 沿源车道按弧长采样，初始间隔建议 200 cm，保留首尾点；弯急处加密。所有计算统一用世界坐标，写入新 Actor 时正确转换坐标，避免 Actor 旋转、缩放造成二次偏移。
5. 对每个采样位置 P，找到对应源道路中线位置 C。取车道切线在水平面的单位方向 T，再求水平法向 N；若 `dot(N, P-C) < 0` 就翻转 N。这样 N 始终朝道路外侧，不受车道点序反转影响。中线匹配应限制在对应路段范围内，防止回头弯处匹配到另一段。
6. 新点为 `Q = P + N × OutwardOffset`。这是真正沿弯道逐点偏移，不能整体平移 Actor，也不能靠放大 Actor 得到平行线。
7. 向下检测目标地面，决定新路径高度；路灯基础路径建议贴地后抬高约 2～5 cm 便于观察。优先沿用现有道路探测对桥面、高架的处理，避免打到桥下地形、屋顶或其他不相关表面。探不到有效地面时记录位置并标记待检查，不静默当成功。
8. 用采样点重建平滑样条，检查弯道插值有没有越出路肩。急弯、自交、短段需要加密或人工修正；数学偏移曲线在急弯处不保证始终平滑无自交。
9. 保留原车道的分段边界，第一版不跨路口自动连接。路口缺口以后按灯位需求单独处理，避免路径横穿路口。

## 命名、显示和重复运行

- Actor label：`light_spline_<原车道名去掉 Lane_>`，例如 `light_spline_MainRoad_R003_-0540_S05`；不能所有 Actor 都只叫 `light_spline`，否则无法追溯来源。
- 大纲文件夹：统一 `light_spline`。
- 每条记录源车道标识、道路 ID 和偏移参数，并加专用生成 Tag，例如 `DeliveryLightSpline`。
- 重跑只替换本脚本生成且属于本次范围的样条，不按文件夹整批删除，也不动手工放置的内容。
- SplineComponent 的未选中、选中样条颜色均设红色；必要时稍微增加编辑器线宽。具体属性能否由当前 UE Python 写入，应在编辑器中先检查；不可写时在蓝图组件详情设置并由实例继承。
- 红色样条是**编辑器可视化**。如果需要游戏运行时也看得到红线，应另外制作可见网格或调试绘制；本需求默认只需编辑器显示。
- 生成后保存关卡，关闭重开验证样条和颜色仍在，再检查是否有额外资产需要保存。

## 验收

- 示例新线在 `-0540` 这一侧继续远离道路中线，没有偏进内侧车道。
- 同一路段正负两侧均向外扩，反向车道没有偏反。
- 直道平行、弯道跟随曲率，坡道和桥面高度合理，无明显穿地、悬空、自交。
- 全部新线位于 `light_spline` 文件夹，红色显示，名称可对应原车道。
- 只生成外侧普通车道的对应线，没有内侧车道或路口转弯线的重复产物。
- 重复执行不会叠加，现有交通车道、路口、车辆逻辑保持正常。
- 输出报告记录输入数、生成数、跳过原因、地面探测失败位置和使用参数；保存重开后结果不丢失。
